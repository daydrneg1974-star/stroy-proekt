# Сборка, обновление и откат на SpaceWeb

Эта инструкция описывает будущий выпуск. **В T07 публикация, push, merge, настройка почты и реальные письма запрещены текущим поручением.** Рабочий сайт остаётся T06: https://stroyinzh-dom.ru/. Отдельный каталог сайта — `/home/p/pridomahru/stroyinzh-dom_ru`; другие сайты не затрагивать.

## Подготовка

1. Получить разрешение на конкретный выпуск. Сохранить текущие незакоммиченные изменения; не использовать разрушительный reset.
2. На выбранном коммите установить библиотеку из lock: `composer install --working-dir=server --no-dev --no-interaction --no-scripts --no-plugins --prefer-dist`.
3. Выполнить `npm run check`, `npm run check:php`, `npm run build`, `npm run verify:release`, обязательный браузерный `npm run e2e`. Зависимости и переменные окружения — в README. Если Chromium недоступен, это незавершённая проверка, не PASS.
4. Сформировать отдельный релиз в новом/пустом каталоге: `npm run build -- /absolute/path/to/release-007`, затем `npm run verify:release -- /absolute/path/to/release-007`. Зафиксировать исходный коммит, SHA-256 архива/манифеста и результаты.
5. Проверить PHP 8.2+, mbstring, openssl, возможность безопасной записи и блокировки вне веб-корня **именно у этого сайта**. Поддержка SMTP у провайдера не подтверждает настройки конкретного виртуального хоста.

Состав новой сборки: `public_html` — 32 файла, `private` — 11 файлов, манифест рядом. Точные allowlist в `scripts/public-files.mjs`. Сборка воспроизводима, хеши CSS/JS рассчитываются по конечным байтам. Не менять готовый релиз вручную.

## Размещение с выключенной отправкой

Перед заменой сохранить обе имеющиеся части сайта и конфигурацию в защищённую копию **вне public_html**. Проверить читаемость и список файлов. Секреты из резервной копии не включать в Git или публичный архив.

- `dist/public_html/*` → `stroyinzh-dom_ru/public_html/`, включая `.htaccess`.
- `dist/private/*` → `stroyinzh-dom_ru/private/`, не под public_html. PHP-файлы и библиотека нужны в этом соседнем каталоге.
- `release-manifest.json`, архив, исходники, документы, тесты и `.qa-preview` остаются вне веб-корня.
- Реального `private/config.php` в пакете нет. При отсутствии конфигурации серверная форма должна возвращать 503, поля выключены, главный черновик/TXT/телефон/WhatsApp доступны.

Подготовить новые каталоги рядом, проверить размеры/хеши и переключить с сохранением прежних. Учитывать согласованность двух частей; конфигурацию и runtime не затирать при будущих выпусках. Не распаковывать репозиторий в public_html. Удалять устаревшие файлы только в пределах этого сайта и при наличии проверенного резерва.

## Включение отправки — отдельный этап

Нужны подтверждённый адрес получателя компании и авторизованный SMTP-отправитель. Публичную почту на сайте добавлять не требуется. При использовании SpaceWeb в официальной инструкции указан `smtp.spaceweb.ru`, SMTPS 465; наличие ящика и допустимый From надо подтвердить. Если нужны SPF/DKIM/DMARC, согласовать отдельные изменения, не вносить их автоматически.

На сервере создать `private/config.php` по примеру, права 0600. Для runtime — отдельный каталог 0700 вне public_html. Допустима переменная `STROY_FORM_CONFIG` с абсолютным путём вне веб-корня. Значения вводятся в защищённой сессии панели/SSH; пароль не посылать в чат. Случайный secret создать на сервере командой из примера.

До включения согласовать фактического оператора/реквизиты, получателя, назначение обработки, текст согласия, хранение/очистку, почтовую инфраструктуру и актуализировать страницу данных. Код требует одновременно `enabled=true`, `privacy_ready=true`, заполненный `consent_text` и корректную серверную конфигурацию. Эти флаги не заменяют юридическую проверку. Добавить и проверить переход с главной к включённой форме; сейчас он намеренно отсутствует.

После отдельного разрешения отправить один явно тестовый запрос, зафиксировать SMTP-принятие и отдельно получить подтверждение адресата. При неопределённом результате не повторять автоматически. Проверить возврат ошибок, 429, отсутствие секретов в ответах и корректное поведение без JS. Нативный POST использует `Referrer-Policy: same-origin` только на request.php; у остальных страниц остаётся no-referrer.

## Проверка после выпуска

Проверить HTTPS без предупреждений, редиректы HTTP и `/privacy`, все публичные ресурсы/хеши, версии CSS/JS, отсутствие циклов редиректов и горизонтального скролла. `.htaccess` для обратного прокси SpaceWeb сохранён, кроме локально подготовленного правила Referrer-Policy формы; поведение Apache на текущем стенде не тестировалось.

Проверить, что `/private/`, `/server/`, `/.git/config`, конфигурация, журналы, тесты, ZIP и манифест недоступны по HTTP; листинга assets нет. Сам запрос `/request.php` выключенной формы должен дать 503, а не 200 с ложным успехом. Статические страницы и ресурсы должны дать 200. Сохранить noindex в HTML/robots/заголовках. Не передавать персональные поля в URL.

Повторить путь «состав → ручные пожелания → копирование/TXT → контакт» и отдельно форму с JS/без JS. Выполнить оставшиеся проверки 200%, физического телефона, завершённого скачивания TXT, обязательный e2e. Только затем обновлять статус опубликованной версии.
