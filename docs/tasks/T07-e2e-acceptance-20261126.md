Использованы официальные Debian-пакеты версии `156.0.8078.108-1~deb13u1`: chromium, chromium-common, chromium-headless-shell. Перед распаковкой SHA-256 каждого файла сопоставлен с официальной страницей Debian. Пакеты размещены в отдельной пользовательской папке, без изменения системных настроек.

Полный Chromium подтвердил версию, но запуск браузерного процесса в этой среде остановился на запрещённом Unix socket (`Operation not permitted`). **Chromium Headless Shell запустился и выполнил сценарии с существующими параметрами теста**, без расширения прав окружения и обхода его ограничений. Полный Chrome и headless shell не следует считать одинаково работоспособными в этой среде.

## Что исправлено в тестах

1. На privacy.html три законные ссылки телефона. Старый locator ожидал единственный элемент и падал в strict mode. Теперь проверяется единственная ссылка в основном содержимом `#content`; ссылки шапки и подвала сохранены.
2. В режиме no-JS снимок длинного блока контактов зависал на ожидании неподвижности при автоматической прокрутке/изменении области захвата. Отдельная диагностика показала меняющуюся координату блока относительно viewport после fill и успешный снимок всей страницы. Для no-JS сохраняется полный снимок без автоматического перемещения к высокому блоку. Проверки видимости, редактирования, ширины и контактов остались. Изменение координаты viewport не объявляется доказательством сдвигов в самой вёрстке; полную внутреннюю причину таймаута screenshot API не установили.
3. Добавлен отдельный тест нативного запрета Clipboard: изолированный контекст Chromium возвращает `clipboard-write=denied`, исходный `navigator.clipboard` не заменяется. Нажатие «Скопировать текст» сохраняет и выделяет весь текст, показывает ручной запасной путь.

## Физический телефон

Пользователь сообщил, что телефон подключён. Доступные инструменты этой сессии работают в облачной Linux-среде: нет `/dev/bus/usb`, список `/sys/bus/usb/devices` пуст, ADB отсутствует, Windows-каталог не смонтирован. Прямого инструмента управления Android или Windows в этой сессии нет. Это ограничение доступности, а не утверждение, что пользователь не подключил устройство.

Проверка физического телефона — **NOT RUN**. Её следует продолжить в локальном Codex на Windows с этой неопубликованной веткой; GitHub main содержит T06. Задание: [T07-phone-handoff.md](T07-phone-handoff.md). Переподключение само по себе не добавит облачной сессии USB-доступ.
