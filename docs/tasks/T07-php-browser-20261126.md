## Подтверждённый дефект и исправление

В форме выбрать параметры дома, очистить площадь, закрыть «Уточнить состав дома» и отправить. Сервер корректно возвращал 422, но поле и текст ошибки оставались скрыты в `<details>`. С JS вызов focus на скрытом поле не помогал. Без JS сервер заново выводил закрытый блок даже при ошибках внутри него.

До исправления оба адресных браузерных сценария завершились FAIL: [доказательство](artifacts/T07/php-e2e-20261126/confirmed-defect/run.log). Теперь `request.js` раскрывает родительский details для сообщения об ошибке перед переводом фокуса. PHP-шаблон добавляет open, если ошибки относятся к площади, комплектации, стенам или дополнительным работам. Правила проверки и отправки не менялись.

В готовом релизе изменились только `public_html/request.js`, `private/form.php` и манифест. Главная, оформление, контакты, Dzit и отзывы побайтно прежние. [Сравнение с предыдущим пакетом](artifacts/T07/php-e2e-20261126/release-comparison.json). Новый SHA-256 манифеста: `daac9bec671bb6d303149c370e3abcf70663f80fbb87a5913fe300e35653e7ec`. ## Изоляция и воспроизведение

Команда `npm run e2e:php` добавлена отдельно от статического frontend e2e. Она собирает временный релиз, запускает PHP 8.4.27 на случайном loopback-порту и Chromium Headless Shell 156.0.8078.108. Каждый сценарий получает отдельную копию обработчика и отдельный журнал. В тестовой копии строго проверяется точка замены вызова SMTP; импорт transport.php удалён, сам файл и PHPMailer туда не копируются. Используется только синтетический текст. Внешние запросы браузера блокируются и проверяется их отсутствие. Подставные конфигурации, runtime и router не входят в релиз; после прогона временная папка удаляется. Исходный отключённый обработчик проверяется отдельно.

```sh
PHP_BIN=/workspace/scratch/0ae38bb7509c/php-runtime/php \
STROY_CHROMIUM_PATH=/workspace/scratch/3eba2c4fa735/chromium-runtime/root/usr/lib/chromium/chromium-headless-shell \
STROY_PHP_E2E_ARTIFACTS=/absolute/path/to/new-evidence-directory \
npm run e2e:php
```

Это пути текущего Linux-стенда; на другом компьютере задать установленные там PHP, Playwright и Chromium. Ошибка запуска не превращается в SKIP/PASS.

В первом прогоне no-JS Playwright click завис на ожидании стабильности summary после прокрутки; этот результат не признан дефектом сайта. Нативный сценарий переведён на реальное клавиатурное управление браузером (focus + Space), без force-click, вызова form.submit() или включения JS страницы. Так получен воспроизводимый FAIL именно на скрытом сообщении, затем PASS после исправления. Это проверка native POST и клавиатуры, не касаний телефона. Полностраничные снимки делаются после возврата прокрутки к началу, чтобы не захватывать фиксированные элементы за видимой областью.
