## Документы и пределы проверки

README/AGENTS/03-dev-architecture/04-user-flows описывают единую сборку из корневых исходников, телефон и подтверждённый владельцем WA Business, Telegram=null, отсутствие MAX/email, ручную отправку и локальный черновик. `docs/status.md` отдельно отмечает код, ещё не выполненную публикацию, реальный переход WhatsApp без подтверждения, отложенные реквизиты/политику и неподтверждённую Windows-папку. Инструкция обновления требует резервную копию вне веб-корня, манифест, публикацию только `public_html`, проверку HTTP и откат целиком. Эти документы не выдают текущую проверку Linux за Windows-копию или техническую минимизацию за правовое заключение.

`git log -1 fc899b3743501248e692ab8b06b4c5dc3cf2697b` возвращает прежний commit `Replace EPDM material catalog with Dzit photo gallery`. `git diff --name-only fc899b3 -- docs/reports assets` пуст: исторические отчёты и медиа не менялись. Три цитаты отдельно защищены проходящим тестом. Удалённые сборщики остаются в Git-истории.

Это не проверка реального аккаунта WhatsApp, звонка, доставки, SpaceWeb Apache/редиректов, сохранности удалённого архива или реальной Windows-копии. Они не выполнялись этим тестировщиком. Непроверенные пункты сохранены явно.

## Как воспроизвести и снять блокер

Из корня проекта выполнить `npm run check`, `npm run e2e`, `npm run build`, `npm run verify:release`. Браузерные зависимости, изоляция сети и переменные путей описаны в [e2e/README.md](../../../../e2e/README.md). Нужен доступный локальный Chromium; затем повторить e2e, изучить реальные скриншоты 320/1440 px и no-JS и обновить вывод новым кругом. Отсутствующий браузер не пропускается и не превращается в PASS.
