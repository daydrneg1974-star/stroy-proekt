## 8. Серверная форма

Публичный request.php обращается к соседнему непубличному private/bootstrap.php. Без реальной конфигурации возвращается **503**, поля отключены; автоматической передачи главного черновика нет. На главной остаются TXT, телефон и WhatsApp с ясным указанием недоступности серверной отправки.

Подготовлена последовательность POST → проверки → атомарная запись попытки → PHPMailer 7.2.0 / SMTPS 465 с проверкой сертификата → достоверный ответ. From/получатель фиксируются сервером, тело текстовое. Строки Unicode, типы, длины, диапазон/шаг, список услуг, согласие и honeypot проверяются. Неизвестный получатель или подмена полей отклоняются. Origin/Referer и CSRF дополняют защиту, но не объявляются защитой от всех ботов.

Лимит новых попыток: 5/IP в час, 100 суммарно. Запись резервируется до транспорта под файловой блокировкой; повтор и 8 параллельных запросов не создают 8 отправок. При таймауте состояние неопределённое, автоматического повтора нет. HMAC-журнал не содержит исходные IP, телефон или текст. При нативной ошибке поля временно сохраняются в серверной сессии вне веб-корня. Сроки и очистка описаны в README как настройки кода, не выдуманная политика компании.

В браузере найдены и исправлены два дефекта новой реализации: политика no-referrer мешала проверке происхождения нативного POST; отсутствующий список extras мог нарушить повторный рендер формы после ошибки. Добавлены адресные проверки. Для request.php политика теперь same-origin, для остальных страниц — прежняя no-referrer.

Без JS: POST → 303 → GET, значения сохраняются после ошибки, перезагрузка GET не отправляет письмо. С JS: блокировка повторного клика, таймаут 15 секунд, доступный статус и ошибки полей. Успех означает только принятие транспортом; получения во входящие не обещаем.

Модульные проверки покрывают весь диапазон площади с шагом 5, три комплектации и оба материала, неизвестные/нечисловые значения, исключение дубля инженерии, порядок опций, повторное добавление и ручные заметки. TXT проверен на уровне Blob/модуля: UTF-8 с BOM, фиксированное безопасное имя, точное содержимое и освобождение object URL, ошибки подготовки. В браузере кнопка работает и показывает «файл подготовлен». Однако API ожидания загрузки завершился таймаутом; **фактическое завершение сохранения на диск не наблюдалось**. Это не заявляется успешным тестом скачивания. Мобильное скачивание на физическом устройстве также не проверено.

## 11. Браузер

Использован локальный PHP-просмотр в реальном облачном Chrome. Главная, privacy и отключённая форма проверены в iframe с CSS-ширинами **320, 375, 390, 768, 900, 1024, 1440**: горизонтального переполнения нет. Это CSS-проверка в настольном браузере, не эмуляция телефона.

Дополнительно: 320×320 и 900×320, открытое меню имеет прокрутку и остаётся доступным; Enter/Escape и закрытие меню по ссылке; заголовок якоря конструктора находится ниже шапки; Clipboard совпадает с черновиком. Без JS главная оставляет меню/поле/контакты доступными и объясняет ограничения.

Изолированная копия серверной формы с подставным транспортом прошла нативный POST: неверный телефон → ошибка поля и сохранённый текст → исправление → принятие единственным вызовом. Реальный обработчик без конфигурации: GET/POST 503, PUT 405, no-store, cookies отсутствуют, ложного успеха и внутренних путей в ответах нет.

У итоговой главной после перезагрузки ошибок приложения в консоли не обнаружено; сообщения служебного расширения браузера к коду сайта не отнесены. Прежние ошибки тестовой формы исправлены и не скрыты. Снимки: [до](artifacts/T07/baseline-desktop.jpg), [после](artifacts/T07/final-desktop.jpg), [390 px](artifacts/T07/final-mobile.jpg).

## 12. Ограничения

- Автоматический npm run e2e не выполнен: в окружении нет доступного Chromium для этого сценария. Ручной Chrome не объявляется его заменой.
- Масштаб браузера 200% не подтверждён; сенсорное устройство, мобильные Safari/Chrome и экранный диктор не проверены.
- Завершённое скачивание TXT на диск не наблюдалось; отказ Clipboard проверен модульно, не через реальное разрешение браузера.
- Реальный SMTP, DNS почты, доставка/получение, звонок и принадлежность аккаунтов независимо не тестировались.
- PHP/расширения/права каталогов и новые Apache-правила именно на виртуальном хосте stroyinzh-dom.ru не проверены. Известная поддержка PHP/SMTP SpaceWeb не заменяет эту проверку.
- Lighthouse/Core Web Vitals и формальная сертификация доступности не выполнялись. Контраст/фокус и нативные элементы сохранены, полного аудита WCAG не заявляем.
- Нет подтверждения локальной папки на Windows владельца. Эта рабочая папка находится в Linux-среде.
