# Архитектура и проверка демоверсии

Статический сайт HTML/CSS/ES modules. `index.html` содержит оформление и контент, `privacy.html` — доступное без JavaScript техническое описание работы с данными, `project.js` — нормализацию, текст состава и фиксированные ссылки мессенджеров, `site.js` — обработчики интерфейса. В коде нет сторонних runtime-пакетов, БД, серверного приёма заявок, аналитики, секретов и платных API.

Клиентский сценарий заявки использует только фиксированные HTTPS-ссылки на номер +74991306616: `https://t.me/+74991306616` и `https://wa.me/74991306616`. Функция `createMessengerLinks` не принимает черновик и возвращает базовые адреса без query/hash. Ввод, добавление состава/темы, восстановление страницы и переход не включают текст в ссылки. Обычные ссылки открываются в новой вкладке с `noopener noreferrer`; у обеих HTML-страниц `referrer=no-referrer`. Автоматического перехода, API-вызовов и скрытой отправки нет. Клиент копирует текст явной кнопкой или вручную, открывает чат, сам вставляет текст и нажимает «Отправить». Успех доставки на сайте не показывается.

Прежние лимиты URL/текста и состояние `needsCopy` удалены: для всех черновиков действует один ручной путь. Копирование и UTF-8 TXT сохраняют весь текст, пробелы и переносы. Clipboard используется только для записи после явной кнопки, никогда для чтения; отказ API выделяет черновик для ручного копирования. Без JavaScript доступны те же прямые ссылки и текстовая инструкция, поле и телефон. Черновик хранится в памяти вкладки, код сайта не отправляет его на сервер и не записывает в постоянное браузерное хранилище. У textarea `spellcheck=false`; рядом просьба не вводить ФИО, телефон, точный адрес, документы и другие персональные сведения.

Отсутствие аналитики, рекламных cookies и серверного приёма текста в коде не исключает инфраструктурную обработку IP-адресов и технических HTTP-параметров. В публичном ответе 22.11.2026 наблюдался защитный cookie Cloudflare `__cf_bm`; значение cookie не сохраняется. География баз/журналов, сроки хранения технических данных и условия обработки у хостинга не подтверждены. Переход в мессенджер передаёт ему технический запрос; дальнейшая обработка определяется правилами внешнего сервиса. `privacy.html` описывает подтверждённые функции и ограничения, содержит официальные ссылки Telegram, WhatsApp и Cloudflare, телефон и возврат. Это не полная политика и не утверждение юридического соответствия или российской локализации.

T05 по результату проверки приватности заменила требование T04 о переносе текста в URL. История T04 не переписывается. Полная политика требует реквизитов фактического оператора и условий обработки/хостинга; реквизиты пока не получены, уведомление РКН по сообщению владельца не подавалось.

Механизмы сверены с [Telegram Deep links](https://core.telegram.org/api/links#phone-number-links) и [WhatsApp Click to chat](https://faq.whatsapp.com/5913398998672934). Разрешение номера Telegram зависит от [настроек приватности](https://core.telegram.org/method/contacts.resolvePhone), WhatsApp требует активного аккаунта. Корректный URL не доказывает доступность аккаунта или доставку. При недоступном чате интерфейс предлагает другой мессенджер или телефон. MAX отложен пользователем; кнопки и заглушки не добавляются.

HTML загружает `site.js?v=<SHA-256 содержимого>`, а контроллер импортирует `project.js?v=<SHA-256 содержимого>`. После изменения project.js нужно обновить его версию в импорте, затем вычислить новую версию site.js для HTML. Автотест проверяет оба соответствия и не позволяет выпустить устаревшие ссылки. Действующий основной адрес — https://stroyengineering-demo-rifkat.daydrneg1974.chatgpt.site/.

Исходники находятся в корне и `assets/`; `scripts/public-files.mjs` задаёт список публичных файлов. `npm run build` создаёт `dist/`, который не является отдельным источником. Документы, тесты и QA-стенды не публикуются. Назначение сборки проверяется до удаления данных.

`npm run check` выполняет синтаксическую проверку и Node tests. Тесты охватывают сочетания конфигурации, перенос и экспорт текста, отказы Clipboard/Blob, безопасность и воспроизводимость сборки. Проверки мессенджеров доказывают неизменность базовых адресов без query/hash для любых черновиков: персональных сведений в синтетических данных, Unicode, спецсимволов, длинного текста, всех комплектаций, восстановления и действий интерфейса. Проверяются полный Clipboard/TXT и отсутствие автоматического копирования при переходе. Публичная страница данных включена в allowlist сборки, локальные якоря и официальные ссылки проверяются. Независимые тесты обработчиков используют Node DOM fixture: они не заменяют браузер.

Браузерная проверка: ширины 320/360/768/1024/1440, обе темы, меню и клавиатура, якорные переходы, конфигуратор, ручные заметки, настоящий Clipboard и скачанный TXT, доступность контента без JavaScript. Для мессенджеров — видимость действий в порядке «скопировать → открыть → вставить и отправить» и неизменные базовые адреса; для страницы данных — переход из контактов/подвала и возврат. Реальные сообщения не отправляются. Протокол исходной демоверсии: `docs/tasks/artifacts/T01/browser-check.md`; исторический сценарий URL — `docs/tasks/artifacts/T04/`, доказательства минимизации — `docs/tasks/artifacts/T05/`. Проверка физического телефона отдельно не выполнена.

Публикация выполняется штатным Sites workflow из отправленного source commit; архив содержит `.openai/hosting.json` и проверенный `dist/`. Идентификатор существующего сайта и публичная аудитория сохраняются. После публикации — проверка live URL. Для отката используется история версий Sites, Git не переписывается.
