# Правила проекта

- Отвечать преимущественно по-русски. Не менять принятый дизайн, отзывы и галерею Dzit вне задачи.
- Текущая площадка — SpaceWeb, https://stroyinzh-dom.ru/. Источник — корень репозитория, `assets/`, `server/`; `dist/` только результат.
- T07 подготовлена с отключённой серверной отправкой. Последующее прямое поручение владельца «коммит | push» разрешило сохранение проверенной T07 в GitHub-ветке `codex/t07-reliability-local`. Это разрешение не включает merge в main, публикацию сайта, DNS, сертификаты, почтовые настройки и реальные сообщения. Прежнее разрешение T06 не переносить на выпуск T07.
- Сайт представляет реальные услуги компании по уточнению владельца. Не возвращать обозначение демопроекта. Состав предварительный, не смета и не договор; не выдумывать цены, объекты и обязательства.
- Проверки: `npm run check`, `npm run check:php`, `npm run build`, `npm run verify:release`; сначала установить PHPMailer 7.2.0 из composer.lock. Перед выпуском отдельно обязателен `npm run e2e` с доступными Playwright/Chromium. Недоступность инструмента — ограничение, не PASS. DOM fixtures не выдавать за браузерные тесты.
- Публиковать только allowlist: 32 файла в public_html, 11 серверных файлов в соседнем private. Манифест, Git, архивы, документация, тесты и секреты вне веб-корня. Сборка рассчитывает хеши; готовые файлы вручную не править.
- Контакты задаются в contacts.json: СтройИнжиниринг, +7 (499) 130-66-16. WhatsApp Business подтверждён владельцем; отсутствующий Telegram = null, городской номер не подставлять. MAX и публичную почту не добавлять. Корректный URL не подтверждает доставку.
- Главный черновик не отправлять автоматически и не сохранять постоянно. Серверная форма отделена и выключена до подтверждённых SMTP/получателя/условий обработки. Нет аналитики, CRM, сторонних виджетов, скрытых сетевых запросов или платных сервисов. Тестировать только подставным транспортом, без реальных писем.
- Сохранить noindex. Документ данных пока технический; не выдумывать оператора, реквизиты и географию хранения. Исторические наблюдения Sites не переносить на SpaceWeb.
- В docs/status.md различать реализованный код, локальные проверки, опубликованный релиз, принятие SMTP и получение письма. Исторические журналы не переписывать.
- Перед будущим обновлением нужна проверенная копия публичной и непубличной частей. Ограничить действия отдельным каталогом stroyinzh-dom_ru. Не затрагивать другие проекты.
- Linux workspace не является папкой Windows владельца. GitHub и Windows-копию считать обновлёнными только после фактической проверки.
