# Правила проекта

- Отвечать преимущественно по-русски. Работать в границах поручения, не менять принятый дизайн, отзывы или галерею Dzit без задачи.
- Единственная текущая площадка — SpaceWeb, `https://stroyinzh-dom.ru/`. Источник — корень репозитория и `assets/`; `dist/` — только результат. Не возвращать активную сборку Sites или скрытый проверочный вариант.
- Проверки: `npm run check`, затем `npm run build` и `npm run verify:release` — без внешних зависимостей. Перед выпуском отдельно обязателен `npm run e2e`: локальная браузерная проверка, для которой нужны Playwright и Chromium. Модуль задаётся через `STROY_PLAYWRIGHT_MODULE` либо `CODEX_PRIMARY_RUNTIME_NODE_MODULES`; браузер — через `STROY_CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`. При отсутствии зависимостей проверка должна завершиться ошибкой, не тихим пропуском. Текстовый DOM fixture не выдавать за браузерную проверку.
- Публиковать только 26 файлов из allowlist в `dist/public_html`. Манифест, архив, документация, тесты и секреты — вне веб-корня. Сборка сама нормализует текст и рассчитывает хеши; готовые файлы и версии вручную не править.
- Контакты: СтройИнжиниринг, +7 (499) 130-66-16; WhatsApp Business по этому номеру подтверждён владельцем. Контакты задаются в `contacts.json`, отсутствующий канал = `null`; Telegram сейчас скрыт, городской номер для него не использовать. Только предоставленные аккаунты, без текста в URL. Почту и MAX не добавлять. Корректный URL не доказывает наличие аккаунта. Не отправлять сообщения для проверки без прямого поручения.
- Черновик не отправлять на сервер, не записывать в постоянное хранилище. Нет backend, аналитики, сторонних виджетов, платных сервисов и скрытых сетевых запросов. Не заявлять об успешной отправке/доставке.
- Сохранить noindex. Политика остаётся техническим описанием до подтверждения реквизитов и условий обработки. Исторические наблюдения Sites не переносить на SpaceWeb.
- В `docs/status.md` различать готовность кода, опубликованный коммит/релиз, фактическую проверку контакта и нерешённые внешние вопросы. Исторические аудиты и журналы задач не переписывать.
- Перед обновлением сохранить проверенный релиз и точку отката; менять только `/home/p/pridomahru/stroyinzh-dom_ru/public_html`. Разрешение на рутинную работу и публикацию учитывать из текущего поручения, повторно не запрашивать.
- Не считать Linux workspace папкой на Windows владельца. GitHub и Windows-копию называть готовыми только после фактической проверки.
