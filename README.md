## Установка и проверки

Нужны Node.js 22+, PHP 8.2+ с `mbstring` и `openssl`, Composer. Для конкурентного PHP-теста нужен CLI Linux с `pcntl`; отсутствие модуля завершает тест ошибкой. Сайт не требует Node.js на хостинге. NPM-зависимости не добавлены. Единственная серверная библиотека — PHPMailer **7.2.0**, закреплена в `server/composer.json` и `composer.lock`, лицензия LGPL-2.1.

```sh
composer install --working-dir=server --no-dev --no-interaction --no-scripts --no-plugins --prefer-dist
npm run check
npm run check:php
npm run build
npm run verify:release
npm run dev
```

`PHP_BIN` задаёт путь к PHP, если `php` отсутствует в PATH. `npm run dev` запускает PHP на локальном порту из `PORT` (по умолчанию 4173); он не публикует сайт. В управляемом окружении просмотр запускается через `sites-preview start <папка проекта>`, второй сервер не нужен.

Перед выпуском требуется отдельный `npm run e2e` (Playwright и Chromium). Модуль: `STROY_PLAYWRIGHT_MODULE` либо `CODEX_PRIMARY_RUNTIME_NODE_MODULES`; браузер: `STROY_CHROMIUM_PATH`. Без этой переменной проверяется реальный `/usr/lib/chromium/chromium`, затем используется браузер, установленный Playwright. Одного launcher `/usr/bin/chromium` недостаточно. Если инструменты недоступны, тест завершается ошибкой, а не пропуском. DOM fixtures и ручная проверка в облачном Chrome не подменяют этот автоматический прогон. Ограничения текущего стенда перечислены в отчёте T07.

26.11.2026 desktop e2e выполнен: **4/4 PASS** в Chromium Headless Shell 156.0.8078.108. Путь к реальному исполняемому headless shell передаётся через `STROY_CHROMIUM_PATH`; дополнительные права окружения для прошедшего прогона не использовались. Проверка включает настоящий браузерный запрет Clipboard без подмены API. [Протокол и команда для текущей Linux-среды](docs/tasks/T07-e2e-acceptance-20261126.md). Это не приёмка физического телефона.

Для проверки нативной формы без реальной почты после сборки можно выполнить `node scripts/prepare-browser-qa.mjs` и запустить dev с `STROY_QA=1`. Маршрут `/__qa/form/request.php` исполняет изолированную копию обработчика с подставным транспортом; PHPMailer в ней не загружается. Эти файлы игнорируются Git и отсутствуют в релизе. Публичный `request.php` при этом остаётся отключённым.

## Что редактировать

- `index.html`, `privacy.html`, `styles.css`, `privacy.css` — страницы и стили. Системные шрифты, локальные изображения, без CDN.
- `navigation.js` — независимое мобильное меню; `site.js` — управление конструктором и черновиком; `project.js` — чистая логика состава, копирования и TXT.
- `contacts.json` — только предоставленные владельцем контакты. Отсутствующий канал = `null`. Сборка подставляет инструкции в HTML, поэтому проверять нужно результат в `dist/public_html`.
- `request.php`, `request.js`, `request.css`, `server/` — отдельная серверная форма.
- `scripts/public-files.mjs` — точные списки публичной и непубличной частей. Сборка нормализует текст, вычисляет SHA-256 и добавляет версии CSS/JS автоматически. Готовые байты не исправлять вручную.

## Серверная форма

`/request.php` — настоящий POST с прогрессивным улучшением через JavaScript. По умолчанию HTML/POST возвращают 503 и ясное сообщение о недоступности; поля выключены. Главная сохраняет текущий путь через телефон/WhatsApp и TXT. Активного перехода к отключённой форме на главной нет.

После отдельной настройки: сервер проверяет поля, происхождение запроса и сессионный токен; фиксирует попытку под блокировкой; передаёт текст PHPMailer; сообщает только о принятии транспортом. Это **не подтверждение получения адресатом**. При ошибке текст сохраняется; без JS используется POST → 303 → GET. Автоповторов нет. После неопределённого результата повторная доставка блокируется.

Получатель, From и SMTP задаются только сервером. TLS проверяется, SMTP debug выключен, порт 465. Лимиты: тело 32 KiB, сообщение 6000 Unicode-символов, до пяти новых попыток/IP в час и 100 суммарно; журнал до 2 MiB/2000 записей. IP и содержимое представлены HMAC, без исходных телефона/текста. Записи попыток очищаются через 24 часа, лимитов через час — при следующих обращениях. Сессия нужна только включённой форме: токен и при нативной ошибке введённые поля, срок 15 минут с очисткой при последующих запросах. Это технические значения реализации, не согласованная политика хранения компании. `X-Forwarded-For` не используется.

`set_time_limit(10)` и SMTP Timeout/Timelimit по 3 секунды ограничивают отдельные операции; это не гарантия общего времени по часам. Клиент ждёт 15 секунд и не повторяет запрос автоматически.

## Конфигурация, публикация и откат

Сборка: **32 файла в `dist/public_html`, 11 в `dist/private`** и манифест вне веб-корня. Пример без секретов: `server/config.example.php`. Рабочий `private/config.php` создаётся на сервере вне `public_html`, права 0600; каталог хранения — 0700, вне веб-корня, без символических ссылок. Альтернатива: `STROY_FORM_CONFIG` с путём к такому файлу. Пароль не пересылать в чат, не помещать в Git, URL, отчёт или скриншот.

`config.php`, `runtime`, журналы, тесты, `.qa-preview`, архивы, Git и манифест нельзя загружать в `public_html`. Установка реальной конфигурации, изменение DNS и отправка писем в T07 не выполнялись. Для включения нужны подтверждённый получатель, SMTP, документы/текст согласия и проверка получения теста после отдельного разрешения. До этого `enabled=false` и `privacy_ready=false`.
